# 机场手记怎样整理黄页

机场手记帮助读者发现厂商、找到入口、比较公开资料。收录可以来自厂商说明、公开评测、社区反馈或维护者提供的材料，不要求维护者逐家购买和实测。

## 信息从哪里来

| 来源类型 | 标识 | 怎样使用 |
| --- | --- | --- |
| 厂商说明 | `official` | 记录厂商公布的套餐、规则和功能，保留链接与日期 |
| 第三方公开评测、社区反馈 | `community` | 注明作者或站点、原始链接与适用条件，将观点归属于来源 |
| 维护者提供的截图 | `screenshot` | 记录截图可见内容，注明拍摄日期是否已知、原图是否公开 |
| 维护者提供的信息 | `owner` | 记录提供内容及已知范围，不自动视作独立验证 |

`facts` 中的每项说明通过 `source` 关联具体来源。厂商自述、第三方观点和维护者体验分别表述；例如“厂商页面标注支持某功能”“某评测在某环境下观察到某表现”。不把这些材料改写成“我们实测稳定”。

可以用自己的文字汇总事实并链接原文，不照搬他人的长篇评测、图片或整套资料。引用第三方结论时注明来源；来源之间有冲突时保留差异，并列出待核验事项。

## 资料状态与分类

| `status` | 展示名称 | 含义 |
| --- | --- | --- |
| `pending` | 待核验 | 已建立条目，仍有来源或主要信息需要核验 |
| `documented` | 有来源资料 | 已整理来源材料，可以追溯主要说明的出处 |
| `paused` | 暂停入口 | 保留历史档案，暂停推广入口 |

这些状态描述资料整理情况。“有来源资料”不等于已核验当前价格、稳定性、安全性或提现能力，也不是认证或购买建议。是否存在 `experiences` 不决定上述状态。

`categories` 是用于查找资料的标签数组。标签仅做分类，不构成性能背书；涉及线路、地区或功能的标签，应结合对应来源阅读。

## 如何比较套餐

有资料时保留币种、价格、计费周期、流量重置规则、使用限制和资料日期。年付折算月费同时显示年付总额，按量套餐与月付分开，首单优惠与续费原价分开。无法确认的内容进入待核验事项，不用猜测填满字段。

## 可选的使用记录

真实体验可以补充黄页，但不是收录门槛。有观察记录时可使用 [体验记录模板](../templates/experience.json)，在 `experiences` 中记录日期、时段、地区、运营商、套餐、客户端、方法、结果、优缺点和局限。没有记录时保留空数组。

数值带上单位与采样条件；没有测过的项目写“未测”。一次测速只代表当时环境，主观感受不能转写为已验证的技术指标。新增观察保留历史，也记录失败和故障。第三方评测优先作为 `community` 来源引用，不冒充维护者自己的体验。

## 公开材料

截图或日志放入 `evidence/<厂商 ID>/` 前，移除邮箱、支付信息、账户 ID、完整 IP、订阅地址、二维码、Token 和浏览器个人信息。原图未公开或无法独立复核时，在来源备注中说明。来源链接、资料日期和未知项同样有价值，不要求每个条目都上传图片。
